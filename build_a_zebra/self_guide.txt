scene.xml - It acts as the actual physical sandbox. It defines the tables, the red ball,
            the joints of the arm, and the friction settings of the fingers.

world_model.hpp & world_model.cpp - This is your World State and Task State database.
                                    world_model continuously listens to the ROS 2
                                    captures the coordinates, stores them safely in C++ variables

trees/zebra_tree.xml - This contains your execution logic divided by your robot’s anatomy (Head, Body, Feet).

main.cpp - This is the ignition switch that boots up the entire ROS 2 C++ node.

package.xml & CMakeLists.txt - They do not run during the simulation; instead, they are active during colcon build.
                                package.xml guarantees that the BehaviorTree software engines are installed in your workspace
                                CMakeLists.txt tells the computer compiler how to stitch main.cpp and world_model.cpp
                                together into a single automated program executable.

CMake is the program that creates compiler instructions.
Without CMake, the computer would not know:
which `.cpp` files belong together,
which libraries are needed,
what executable name to make.

C++17 is a language standard enables modern C++ features:
    - std::make_shared
    - std::make_unique
    - structured modern C++ syntax

These do not normally stop compilation. They make the compiler tell you about suspicious code. (add_compile_options)
    - Wall       Enable common warnings.
    - Wextra     Enable additional useful warnings.
    - Wpedantic  Warn when code is not fully standard C++.
        |__ unused variables
        |__ missing return statements
        |__ unsafe conversions
        |__ possible programming mistakes

ament_target_dependencies(...) says:
“This specific executable, zebra_bt_node,
needs these ROS packages when compiling and linking.”

target_link_libraries(...) says:
“zebra_bt_node uses BehaviorTree.CPP code,
so include that library in the final program.”

1. Colcon finds package.xml.
2. Colcon sees that the package uses ament_cmake.
3. CMake reads CMakeLists.txt.
4. CMake finds ROS and BehaviorTree.CPP dependencies.
5. CMake compiles all five .cpp files.
6. CMake links them into zebra_bt_node.
7. CMake installs zebra_bt_node.
8. CMake copies trees/ and resources/ into install/.
9. ROS can now locate and run the package.
